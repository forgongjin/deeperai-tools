## 🔴 P0 — 阻断级问题

### P0-1：CSS 变量命名冲突 — 同页两个 accent 变量指向不同颜色

**严重程度**: 🔴 阻断  
**影响页面**: 28 页

所有页面通过 `<link rel="stylesheet">` 引入共享 `assets/css/style.css`，其中定义：
```css
--color-accent: #6366f1;   /* 靛蓝 Indigo */
```

但大量页面在自身 `<style>` 块中又定义了**短变量名 `--accent`**，且值各不相同，导致同一页面上 `var(--color-accent)` 和 `var(--accent)` 指向不同颜色：

| 页面分组 | 页面内 `--accent` 值 | 与 `--color-accent` 的关系 | 影响 |
|---------|---------------------|--------------------------|------|
| **中文博客文章** (3页) | `#0984e3` 蓝色 | ❌ **不同色** | 文字链接蓝色，但按钮/装饰靛蓝 |
| **英文博客文章** (6页暗色风格) | `#6366f1` | ✅ 相同 | 无冲突 |
| **英文博客文章** (4页亮色风格) | `#0984e3` 蓝色 | ❌ **不同色** | 文字链接蓝色，但按钮/装饰靛蓝 |
| **image-toolbox** | `#6366f1` | ✅ 相同 | 无冲突 |
| **pdf-toolbox** | `#f97316` 橙色 | ❌ **不同色** | PDF 工具箱的 `--accent` 和 `--color-image-accent` 同色 |
| **DE 工具占位页** (2页) | `#0984e3` 蓝色 | ❌ **不同色** | 占位按钮蓝色，共享 nav 靛蓝 |
| **FR 工具占位页** (2页) | `#0984e3` 蓝色 | ❌ **不同色** | 同上 |
| **about/contact/privacy(中英文)** (6页) | `#6366f1` | ✅ 相同 | 无冲突 |
| **en/admin/dashboard** | `#6366f1` | ✅ 相同 | 无冲突 |

**根因**: 页面内部 CSS 用 `var(--accent)` 引用颜色，但共享 `style.css` 用 `var(--color-accent)`。当两个变量不同值时，同一页面上不同元素颜色不一致。

**修复方案**:
- 方案A（推荐）: 全局统一使用 `--color-accent`，删除所有 `--accent` 定义，用全局变量 `${--color-accent}` 替换所有 `var(--accent)` 引用
- 方案B: 按页面类型在不同 `:root` 中覆盖 `--color-accent` 值（但需确保不再定义 `--accent`）

### P0-3：6 篇博客文章覆盖了共享导航 CSS

**严重程度**: 🔴 阻断  
**影响页面**: 6 页

以下英文博客页面在自身的 `<style>` 中添加了针对 `.nav` 的覆盖规则：

| 文件 | inline CSS 覆盖 |
|------|----------------|
| `en/blog/add-watermark-pdf-guide.html` | `.nav { margin-bottom:32px; } .nav a { color:var(--sub); margin-right:16px; ... }` |
| `en/blog/batch-image-compression-guide.html` | 同上 |
| `en/blog/compress-pdf-file-size-guide.html` | 同上 |
| `en/blog/online-tools-privacy-comparison.html` | 同上 |
| `en/blog/split-pdf-online-free.html` | 同上 |
| `en/blog/why-image-compression-matters-seo.html` | 同上 |

这些 inline 规则会覆盖共享 `style.css` 中的 `.nav` / `.nav a` 样式，导致这些页面的**顶部导航栏出现双重样式**（共享 + 本地），表现为：
- 导航项间距不一致
- 颜色可能错乱
- `margin-bottom` 值不同

另外，这些页面的 `nav` class 匹配数显示为 `nav: 6`，而正常页面为 `nav: 5`（多了一个 `.nav` inline CSS class 定义）。

**修复**: 删除这些页面中针对 `.nav` 的 inline CSS 覆盖，统一使用共享 `style.css`。如果需要博客导航特殊样式，使用独立 class 如 `.blog-back-nav`。

### P2-2：CSS 加载顺序不一致

**影响页面**: 约 15 页

| 加载顺序 | 页面示例 | 
|---------|---------|
| `<link rel="stylesheet">` 先 → `<style>` 后 | about、contact、image-toolbox、pdf-toolbox、privacy 等 |
| `<style>` 先 → `<link rel="stylesheet">` 后 | de/about、de/contact、de/index、de/privacy、en/index、fr/about、fr/contact、fr/index、fr/privacy、en/blog/index、blog/index |

当 `<style>` 在 `<link>` 之前时，共享 CSS 会**覆盖**部分 inline 样式。这在当前设计下影响较小（因为两者都定义了相同的变量名），但可能在某些边界场景造成意外覆盖。

**推荐**: 统一为 `<link rel="stylesheet">` 在最前，确保共享样式作为 baseline。
